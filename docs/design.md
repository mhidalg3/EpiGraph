# Implementation notes

The authoritative specification is `Workflow_Assurance_Design.md`. This file records how it is realized.

## Model and execution

- `ModelBundle` (`src/model/schemas.ts`) is the single source of truth: entities (eight kinds), activity contracts W01–W14, explicit technical grants, normative authorization rules, controls, A1–A3 automation patches, C1–C6 repair patches, named mutation variants, suites, cases and economics. The display graph is projected from it.
- Contracts use closed predicate/effect unions (no expression strings, no JavaScript). Evidence predicates (`validBeneficiary`, `validApproval`, `hasClearance`, `payloadBound`) are implemented in `src/engine/evidence.ts`.
- Technical ability (`capabilities.ts`), normative authorization (P03) and implemented enforcement (controls attached to contracts) are separate. Only an attached, implemented control may disable a transition or route it into a blocked-attempt outcome. Policy monitors (`policies.ts`) inspect the events of every transition and the pre-execution state; they never gate.
- Exploration (`explore.ts`) is breadth-first with exact canonical state keys, checks initial invariants and every transition before deduplication, and records the shortest witness per hazard. Hitting `maxStatesPerCase`/`maxTransitionsPerCase` yields `partial` coverage: absent findings are `unknown`, never a pass.
- Patches are applied immutably in order: variant → automations (sorted) → controls (sorted). Conflicting assignments inside one stage are rejected.

## Status vocabulary

`analysisStatus` (complete/partial/invalid), `policyStatus` (satisfied_in_model/violated/unknown), `goalStatus` (satisfied/failed/unknown), `optimizationStatus` (optimal_in_catalog/best_verified_found/no_feasible_design/unknown) are kept separate. Green requires complete analysis with satisfied policies and satisfied goals.

## Case partition

Legitimate cases restrict branch domains to correct extraction and successful acknowledgement. Incorrect extraction is modeled only in the declared `CASE-EXTRACTION-MISMATCH` exception case (requires A1) whose required outcome is `invoice_mismatch`; settled-but-unacknowledged retries only in `CASE-RETRY-UNCERTAIN`. Mutation suites (`stale-approval`, `external-transfer`, `uncertain-retry`, `assurance-boundaries`) and named variants keep hostile mutations out of the default flagship verdict.

## Economics

`value.ts` executes one nominal valid route per economic class (940 routine invoices, 60 paid supplier events, 40 unpaid supplier events by default) and charges stipulated human minutes per activity branch to human actors only. Review capacity counts extra human minutes relative to the requested unrepaired design. Platform cost is platform-wide (USD 700/month + USD 3,600 setup amortized over 12 months) whenever any automation is requested. Values are capacity-equivalent, not cash savings.

## Reports

`src/engine/report.ts` produces deterministic JSON and Markdown exports with SHA-256 hashes (web crypto) of the canonical model, design and policy inputs. Hashes are reproducibility identifiers, not attestations. Imported reports restore their embedded model/design for rerun and replay; an imported verdict is never trusted.

## Import limits

Model imports are rejected above 1 MiB before parsing. Report imports (which embed the model plus witnesses) use an explicit 16 MiB cap, and the embedded model must itself be under 1 MiB. Fixture JSON is generated by `scripts/gen-fixtures.mjs`.
